# 束线联锁控制器规程升级 · 静止输出复核（ioco）与离线测试套件（W-method）

工程师在网页分别录入**旧规程**与**候选规程**（有限位置、初始位置、输入命令、
带输入或输出标签的迁移，输出可明确标记为“静止”），提交后由后端接口按
**ioco（输入输出一致性）**语义复核：纳入内部静默迁移（`tau`）与可观察静止（`δ`），
候选在旧规程可执行历史后可能给出的每项输出，都必须为旧规程在同一历史允许。

录入旧规程后，工程师还可填写现场控制器的**最大稳定位置数**，由后端生成一份
**有限的离线一致性测试套件（W-method）**，并将逐轮“发送命令、收到输出或静止”
的现场记录回放，确认候选控制器是否已暴露行为越界。

## 判定方法（双规程复核）

- 对“候选位置闭包 × 旧规程位置闭包”做广度优先共归纳探索：两侧先求 `tau` 闭包，
  再沿旧规程的悬挂迹（输入、输出、`δ`）同步推进。
- 每到达一对闭包，核对 `out(候选) ⊆ out(旧规程)`；越界即不一致。
- 反例展示：按 ASCII 顺序确定的**最短历史**、两侧**逐步闭包状态集**、
  **候选输出**与**旧规程允许输出**。
- 不使用状态名对应、不做有限长度枚举、不做随机回放；
  仅位置改名而行为相同的两份规程判为一致。

## 套件生成（W-method）

- **确定化**：先把旧规程含内部静默（`tau`）与可观察静止（`δ`）的语义确定化为
  “命令 → 观察”确定机：机器状态为规程位置的稳定闭包（tau 闭包后仅允许 δ 可观察），
  每条边为“闭包允许的输入命令 + 该命令后唯一的可观察结果”。
- **仅在每个闭包允许时发出命令**；若旧规程在同一命令后存在多个可观察结果
  （或无可观察结果、闭包在轮次之间不稳定），**拒绝生成**而不任选一条。
- **套件构造**：以**状态覆盖**（P）、**迁移覆盖**（经 `K = m - n + 1` 层中间序列并入）
  与**区分后缀**（W）构造 W-method 套件，其中 `n` 为确定化并化简后的稳定状态数，
  `m` 为工程师填写的最大稳定位置数。任何不超过 `m` 个稳定状态的**确定实现**，
  通过全部用例当且仅当它在该范围内与规程一致
  （引擎级穷举测试逐台核对过该保证）。
- **完备性边界**：上述保证要求确定化机器各闭包允许的命令集合处处一致
  （等价于输入完备机），或机器无循环（可执行命令树有限）。循环内外允许的
  命令集合不一致时，确定实现可合并规程角色、把越界行为藏到 `n·m` 深度，
  任何多项式规模 W-method 套件都无法保证暴露，故**拒绝生成**，绝不给出猜测结论。
- 不使用固定深度枚举、随机命令或位置名称替代；
  用例编号（`T001`、`T002`…）与套件标识（`S-…`）由规程与上界完全确定，稳定不变。

## 现场记录回放

- 记录格式：每行一轮 `命令 观察`（空白分隔；`#` 开头为注释，空行跳过）。
  命令为已声明的输入命令（可带 `?` 前缀）；观察为 `!输出` 或 `δ`/`delta`（静止）。
- 回放逐轮核对：命令须与用例步骤一致，观察须落在**每步允许观察**内；
  页面展示首个失败轮次。
- **静默后报警**（观察越界）、**终止用例后继续输入**判为回放失败；
  **未知标签**（未声明命令、非法观察写法）、**未知用例编号**按行定位拒绝（HTTP 422）；
  **过期测试标识**（与当前套件不符或已失效）以 HTTP 409 清楚拒绝；
  以上拒绝均使页面清除旧回放结果。重新生成套件即替换当前套件，旧标识随之过期。

## 录入语法

- 位置 / 输入命令：逗号或空白分隔的名称列表。
- 迁移：每行一条 `源 -> 目标 : 标签`；`#` 开头为注释。
- 标签：`?命令` 输入（须先在输入命令中声明）；`!名称` 输出；
  `tau` 内部静默迁移；`delta` 将输出明确标记为“静止”（δ）。
  没有任何输出 / 静默 / 静止迁移的位置被视为可观察静止。
- 非法标签、悬空迁移、缺少初始位置、同一标签下重复状态声明等，
  接口将按侧别、字段与行号定位反馈，页面同时清除先前结论。

## 接口

- `GET /`：复核页；`GET /healthz`：健康检查。
- `POST /api/check`：请求体 `{"old": {...}, "candidate": {...}}`，
  每份规程含 `locations / initial / inputs / transitions` 四个文本字段。
  - 复核通过受理：`{"ok": true, "result": {"verdict": "consistent" | "inconsistent", ...}}`
  - 录入非法（HTTP 422）：`{"ok": false, "errors": [{side, field, line, message}, ...]}`
- `POST /api/generate`：请求体 `{"old": {...}, "maxStates": m}`。
  - 生成成功：`{"ok": true, "result": {"suite": "S-…", "states": n, "bound": m,
    "distinguishing": [[...]], "cases": [{"id": "T001",
    "steps": [{"command": "cmd", "allowed": ["δ"]}, ...]}, ...]}}`
  - 规程非法、同一命令后多个可观察结果、闭包不稳定、循环内外允许命令集合不一致、
    上界小于稳定状态数等（HTTP 422）：`{"ok": false, "errors": [...]}`
- `POST /api/replay`：请求体 `{"suite": "S-…", "case": "T001", "record": "cmd δ\n..."}`。
  - 回放结论：`{"ok": true, "result": {"verdict": "passed" | "failed" | "incomplete",
    "firstFailure": {"round", "reason", "allowed", ...} | null, ...}}`
  - 过期测试标识（HTTP 409）、未知标签 / 未知用例编号（HTTP 422）：
    `{"ok": false, "errors": [...]}`

## 运行（Docker / Compose）

```bash
docker compose up --build web          # 打开 http://localhost:8080
PORT=9000 docker compose up --build web  # 可配置端口
```

健康检查已内置于 Dockerfile 与 Compose（`GET /healthz`）。

## 验证（verify 服务）

```bash
docker compose up --build --exit-code-from verify verify
```

`verify` 依次执行**代码测试**（单元测试，含 W-method 保证的穷举核对）、
**构建检查**（源码编译、文件齐备、模块导入、引擎级核对）、**HTTP 冒烟**
（健康检查、复核页、经接口核对“静默后报警”反例、一致对照、非法录入反馈）、
**套件与回放**（静默闭包后的静止通过、越界报警失败、终止后继续输入、
未知标签、过期测试标识、非确定旧规程拒绝生成、双规程复核接口仍可用），
完成即退出并打印退出码（0 通过 / 1 失败）。

## 本地运行（无 Docker）

```bash
python3 server.py                 # PORT=9000 python3 server.py 可改端口
python3 -m unittest discover -s tests -v
WEB_URL=http://127.0.0.1:8080 python3 verify.py
```
